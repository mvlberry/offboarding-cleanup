# 开发凭据与交接资料

这里整合 Computer Repair Skill 的 `credential-cleanup`、`local-data-audit` 和备份验证思路，并补充开发机常见凭据。只加载请求涉及的类别；不运行整机秘密内容扫描。

## 凭据类型与处理

| 对象 | 有界盘点 | 获准后的处理 | 复核重点 |
|---|---|---|---|
| SSH 私钥/证书 | 当前用户 `.ssh` 及用户指定的自定义位置，记录候选文件类型和年龄；不要读取私钥正文 | 指定私钥及副本按清单处理，从实际使用的 ssh-agent 移除对应身份；Git Bash/WSL/Pageant 等分别核对 | 磁盘文件和 agent 缓存是两项；GitHub/GitLab/服务器上仍可能授权 |
| SSH 远端授权 | 只记录应由谁处理的服务，不转储服务器清单 | 仅在明确授权时移除对应远端公钥/证书授权；共享密钥需协调替换 | 删本机私钥、删 `known_hosts` 均不等于远端撤销 |
| Git 与 GitHub/GitLab CLI | 识别 credential helper 和 CLI 是否有会话，只返回脱敏结果 | 使用对应受支持的注销/helper 删除流程，处理磁盘与系统库中的副本 | Git 姓名/邮箱不是身份凭据；CLI 本地注销不能证明 Token 在服务端失效 |
| npm、PyPI、Docker、云 CLI、Kubernetes | 盘点已知配置文件是否存在、所属工具/账号别名；Kubeconfig 可能含私钥或 Token | 使用工具支持的注销；无注销功能时，仅按明确目标移除凭据配置。云端撤销/轮换另列 | 文件内容、完整 `docker inspect`、`kubectl config view --raw` 可能泄密；不直接回显 |
| 环境变量、`.env`、`.netrc`、凭据文件 | 只记录变量名或文件位置，区分当前进程、用户、系统、启动脚本/CI 配置 | 仅移除批准的条目；系统级配置和共享服务另确认 | 修改持久化值不会自动清空既有进程；记录是否需重启应用/退出系统 |
| Windows 凭据管理器 | 由界面或受支持接口查看选定服务类别；不转储凭据内容 | 删除确切条目，必要时先退出产生该条目的应用 | 工作/学校账户、WAM/SSO、Windows 登录本身须分别识别，不直接删除 DPAPI/Vault 根目录 |
| macOS 钥匙串 / Linux Secret Service | 只定位批准的条目/集合，不导出整个库 | 系统界面或官方工具删除指定项 | iCloud/桌面账号可能同步恢复；不清空整个钥匙串以代替单项处理 |
| Wi-Fi、VPN、Kerberos | 仅确认已保存配置和票据是否存在；避免输出密码与内部域名 | 移除指定网络/VPN 账号；Kerberos 使用平台正确工具（如 Windows `klist purge`，类 Unix `kdestroy`），确认影响 | 断网/票据清理可能立即中断本次工作，排在所依赖动作之后 |
| GPG、客户端证书、PFX/P12、通行密钥 | 盘点位置/存储类别，不读取秘密 | 按选定证书或密钥处理；硬件钥匙和同步通行密钥另列 | 不删除 TPM/Windows Hello 整体状态、BitLocker 恢复信息或唯一恢复凭据作为一般清理 |

`~` 仅是当前目标用户位置的示意，不把本 Skill 所在账号的目录当作所有机器的固定路径。Windows OpenSSH 常见于 `%USERPROFILE%\.ssh`；自定义 `IdentityFile`、WSL 家目录和便携工具要单独确认覆盖。

SSH `authorized_keys` 管理“别人进入这台电脑”的授权；不是这台电脑访问外部的私钥。`known_hosts` 是连接过的主机记录；若用户希望清理此类隐私记录，可列为独立项，不盲删整棵 `.ssh`。

需要钥匙指纹进行匹配时在本机受控处理，只返回必要的脱敏标识；不把 SSH config、Git remote（可能嵌入 Token）、CLI auth 状态的原始输出直接传入聊天。不要测试凭据是否失效时顺手登录生产服务；优先通过账号安全页的撤销结果验证，真实连接测试需在该服务授权内。

## 本地数据盘点

依据用户范围检查桌面、文档、下载和指定工作目录中的文件数量/大小；不读取正文来判断“个人还是公司”。对于 `.env`、`.pem`、`.key`、`.pfx`、`.p12`、`.kdbx` 等只记候选类别。文件不存在、无权限和未检查必须区别。

还需考虑：邮件离线缓存、QQ/微信/飞书下载附件、代码目录、压缩包中的副本、远程桌面配置、剪贴板/终端历史及 AI 会话中的秘密残留。只在这些类别获准后处理，不把历史记录直接打印出来，不清理企业审计日志。浏览历史清理不会删除 Downloads 里的实际文件。

对代码目录先核对是否有未提交/未推送工作，不自动推送、上传、删除仓库或重写 Git 历史。若凭据已进入 Git 历史，清工作区文件不能消除历史副本，先安排凭据轮换，仓库历史处置单独计划。

## 同步、备份与交接

1. 用元数据确认同步服务和目标目录；OneDrive、Google Drive、Dropbox 等的本地占位符不能证明完整备份。
2. 用户要求保留工作成果时，确认授权接收者、交接位置和恢复方式。只读核验同步完成或在独立位置做获准的抽样恢复，不覆盖现有文件。
3. 本机清理而保留云端时，先用客户端解除此设备同步，再核对目标是已脱离同步的本机副本；未解除时不直接删同步目录。
4. 不自动备份会话数据库、Cookie、密码库、密钥或聊天档案。用户确需保留的敏感副本应放到其批准的受保护位置，并列入交接后的残留检查。
5. 正常离职先完成必要交接；如果用户明确说明凭据泄露，优先协调撤销/轮换，保留所需调查记录，再安排本地清理。

## 外部权限

对每项凭据分别记“本机移除”和“远端撤销”。服务端步骤可能包括指定设备会话、OAuth 授权、个人 Token、SSH 公钥和企业账号权限；只处理已授权对象。由管理员负责的项列出服务、账号别名、请求动作和验证方式，不擅自发邮件/消息或创建工单。

例如：本机 `gh` 已退出 + Git 凭据库已移除，只能报告本机状态；没有看到 GitHub Token 撤销结果时，远端状态仍为待处理。
