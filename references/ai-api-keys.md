# AI 客户端与切换工具：API Key 清理

用于已在本机发现的 Cherry Studio、CC Switch、Codex++、CC Mesh，以及其他 AI 客户端、Switch/供应商切换器、本机网关、代理和登录插件。只编辑 Skill 时不检查实际安装和密钥。本页补充[本机重新认证](local-reauth.md)，不要求 API Key 模式出现扫码页。

## 目标与范围

目标供应商不能再使用这台电脑保留的旧密钥、OAuth 或代理授权；再次使用应要求重新提供凭据或完成授权。界面可正常打开，匿名功能、本地无认证模型、未选中账号可以继续使用。退出客户端账号、关闭供应商、隐藏密钥框、切换当前供应商或卸载软件，都不能代替清除存储。

本机网关的入站认证与上游认证不同：客户端留空 Key、任意占位值或连接 `localhost`，仍可能经网关使用保存的上游密钥。只有核实不依赖目标凭据的本地/匿名服务才能标为不适用；不能把无入站认证的代理当作无凭据的本地模型。

“清理该工具全部 API Key”包括该本机实例中全部获准供应商、禁用配置、非当前配置和多密钥轮换槽位。只指定一个供应商/账号时保留其他项。仅清本机不默认撤销供应商云端密钥或删除云备份；远端轮换另列结果。

## 先建立有界的凭据去向表

从[发现清单](installed-app-discovery.md)确认产品、发布者/官方仓库、版本、安装渠道及实际数据目录；便携版和自定义数据目录分别记。不能根据“switch”名称猜为某一产品，也不搜索全盘所有含 `key` 的文件。

每个目标记录下列实际存在的层级；只输出别名、字段名称、是否存在、数量、路径类别和状态，不输出完整配置、密钥片段/哈希、请求头或带凭据的 URL。需要解析配置时在本机受控代码内进行，仅返回白名单元数据，禁止将原文传入模型或在线扫描器。

| 层级 | 检查内容 |
|---|---|
| 管理器存储 | 全部目标供应商/端点/项目/工作区的密钥槽、API Token、OAuth/刷新凭据，含禁用、归档和未应用的配置档案；自定义认证头、URL/查询参数或辅助命令中的凭据 |
| 使用端 | 工具已写入的 CLI/IDE/插件配置、`.env`、凭据库，以及已确认配置引用的密钥文件或辅助程序；不执行未知 helper |
| 环境与运行态 | 目标进程、托盘/代理、当前及持久化用户变量、启动脚本；仅核对已定位的认证字段，不转储整个环境或进程内存 |
| 恢复来源 | 代理接管/退出恢复、供应商切换、OAuth stash、自动同步、配置导入、旧版本迁移源；不能清了当前值又被写回 |
| 本机副本 | 已配置目录里的自动/手工备份、SQL/JSON 导出、`.bak`、首次写入快照、实际留下的临时文件；依据设置/文件元数据有界追踪 |

API Key、系统账号 OAuth、应用自身云账号、WebDAV/S3/第三方集成凭据可能互不相同。分别定位授权范围；模型 Key 删除不能算其余凭据已清。混合业务数据或未授权的关联使用端单列，不能擅自扩展删除。

## Cherry Studio

本页依据官方文档及 `v2.1.10` 源码核对；执行时匹配实际版本，不套用同一数据库路径或跨版本 SQL。

1. 从当前版本设置确认真实数据位置及是否有旧版本数据。在模型服务/供应商管理中逐个处理目标供应商的**全部密钥槽**，包括禁用项和轮换列表；预置供应商可能无法删除，使用当前版本支持的单密钥移除/清空方式并确认持久化。只关闭服务开关不算清除。
2. 按实际使用证据核对供应商的其他认证配置、OAuth、搜索/翻译/图像等独立服务及 MCP 的环境变量/认证头。它们可能不与聊天模型共用 Key；仅处理已授权项，保留聊天、助手、知识库、附件、非认证设置。
3. V2 使用 SQLite 数据层，供应商密钥和认证配置由 `ProviderService` 管理；V1 的 Redux Persist/Dexie 等存储与迁移保留数据另核对。升级后的当前设置已空，不能证明 V1 源和旧目录没有副本。优先应用支持的选择性操作，不能删除整库、全部 Local Storage/IndexedDB 或点“重置全部数据”来替代密钥清理。
4. 如本机启用 API Gateway/API Server，区分其**本机网关 Key**与**上游供应商 Key**，以及实际存在的配对授权。先理清正在依赖网关的本机客户端，再按授权停止网关/自动启动并处理相应凭据。只停监听或换网关 Key 不会删除上游 Key；不把配对设备远端副本当成本机清理对象。
5. 核对本机备份目录、已下载的恢复包和旧版本迁移数据。官方说明全量备份包含供应商 API Key；“轻量备份”保留设置，也不能视为脱敏。先停止本机自动备份/同步写回，按清单移除获准的本机凭据副本；保留云端，另记云备份仍可能含 Key。不要为了回滚清理而新建带 Key 的全量备份。

清理后正常重开，核对全部目标密钥槽、其他认证来源与本机网关恢复状态。若混合数据库或备份不能可靠选择性处理，报告保留数据与密钥清理的冲突；不为了凑齐结果抹掉聊天档案。

## CC Switch

以下是官方提交 `9bd8fe510db8a94e39e2a3c5d14c9448e03f23f2` 的定位线索，不是固定删除列表。`~` 指目标用户；目录、文件及字段需先核实当前版本和实际存在证据。

| 位置/来源 | 处理重点 |
|---|---|
| 默认 `~/.cc-switch/cc-switch.db` 或实际自定义配置目录 | 所有目标供应商、项目配置和共享配置中的 Key；删当前供应商不等于其他供应商/备用配置已清 |
| 实际受管 CLI 配置 | Claude 的 `settings.json` 认证变量/`apiKeyHelper`，Codex 的 `config.toml` 供应商认证字段，Gemini 的 `.env` 等；按实际客户端版本映射，不仅处理管理器数据库 |
| 本机代理/路由 | `PROXY_MANAGED` 等占位符并非真正上游 Key；真实凭据仍可能在管理器里。暂停自动切换/恢复，核对代理和使用端的最终配置 |
| 设备本地状态 | `settings.json`、`live-state.json`、`codex-login-stash.json`、`backups/live-first-write/`；该版本这些仍在默认目录，不随自定义配置目录迁移，因此两处都核对 |
| 其他实际存在的账户存储 | 如 `copilot_auth.json`、`codex_oauth_auth.json`、`xai_oauth_auth.json` 的目标 OAuth/刷新凭据；不能用删除 API Key 代替注销这些会话 |
| 本机备份/导出/迁移残留 | 数据库备份、SQL 导出、环境变量备份、首次写入前的 CLI 配置快照、旧 JSON 与已确认旧目录；这些可能重新带回 Key |

该提交的文档把 Codex 第三方 Key 放在 `config.toml` 的供应商认证字段（如 `experimental_bearer_token`），官方 OAuth 则走 `auth.json`。其他版本也可能使用 `OPENAI_API_KEY` 等形式；只删其中一处不能证明全部已清。`codex-login-stash.json` 还可能在切回官方供应商时恢复登录。

先核对该版本停止接管、切换供应商、退出代理时的恢复行为，在获准范围内正常结束写入者；**所有恢复/写回动作完成后，再清理并复核实际 CLI 配置**。若清理所用的 AI/终端依赖它，先交付接续步骤，将对应动作放最后。不要凭文件名手工改 `live-state.json` 或任意执行 SQL。

该提交的路由说明明确：回到直连或退出可能写回之前的直连配置，下次启动还可能重新接管；路由目标和故障转移队列也需核对。若供应商仍被引用而无法删除，先按当前版本支持的方式处理获准的激活/路由引用，不能反复强删或换另一把仍有效的 Key 作为完成状态。

操作本身也会产生副本：已核对版本的首次写入会备份原 CLI 配置，环境变量删除会创建备份，数据库导入前也会备份。清理完成后再次有界检查新生成副本，不能只检查操作前的备份列表；也不要用“导入空配置”或清空整个数据库代替选择性删除。

## Codex++（CodexPlusPlus）

这里指官方项目 `BigPizzaV3/CodexPlusPlus`，依据提交 `00a1355850cec86d606cf09331cfbc5c66d6512d`。同名分支、旧版本及便携实例需先核对身份，不能默认共用下列存储。

- **两套供应商池分别清理**：`settings.json` 的直连配置与 `gateway.json` 的网关配置独立，导入供应商是复制，不是共用引用。目标配置可能有 `api_keys` 多密钥列表、`configContents`/`authContents` 内嵌凭据及如 `vlmApiKey` 的额外服务 Key；网关还保存本机访问 Token。只清直连界面上的一项不会清空网关或轮换 Key。
- **实际实例与路径分别定位**：该版本默认状态目录为 `~/.codex-session-delete/`，可由 `CODEX_PLUS_STATE_DIR` 改写，主设置文件还可通过路径指针重定向。根据实际设置和实例元数据定位，别把目录名误当作待删除命令。隔离多开实例、实际 `CODEX_HOME` 及被接管的其他 Agent 配置分别核对；不因默认目录为空而判定没有凭据，也不扫描未发现的用户/实例。
- **接管与退出恢复完成后再清使用端**：网关/订阅账号与直连认证分别处理。关窗口可能仍有网关在运行；断开接管或退出时可能恢复原直连配置，下次启动还可能再次接入。按当前版本关闭本机自动接入/恢复、正常处理相关网关和目标订阅会话，再复核所有获准使用端的最终认证字段；不能只删网关池或停止监听。
- **把实际产生的备份纳入清单**：接管前的原 Agent 配置可归档到 `<状态目录>/backups/agent-<id>-before-gateway.json`；直连配置备份可在 `<实际 CODEX_HOME>/backups/codex-plus-live-<timestamp>/` 保存 `config.toml` 和 `auth.json`。正常断开恢复可能重新带回凭据。只处理已核实、已获准的本机副本，清理结束后复查新副本，保留其他工作资料。

通过产品支持的选择性移除处理供应商、网关 Token 与目标订阅凭据，不因状态目录包含密钥而递归删除全部会话、项目或设置。若当前操作依赖 Codex++ 网关/会话，遵循依赖最后处理规则。正常重开后核对直连池、网关池、全部已发现实例与使用端均不恢复目标凭据；无法观察的项记录待验证。

## CC Mesh（ccMesh）

这里指 `VkRainB/ccMesh`，依据提交 `7cd325e3936698f3ef8b94760fdd6da187fef5dc`（源码版本 `0.2.11`）。主库在应用实际解析的 `<app_data_dir>/ccmesh.db`；先核实当前用户实例的数据目录，不硬编码跨系统路径。程序标识为 `com.ccmesh.desktop`，不是可直接删除的目录清单。

- **端点与多凭据分别处理**：`ccmesh.db` 中存在 `endpoints.api_key` 与 `endpoint_credentials.api_key` 两层，全部获准端点及其密钥都需核对，包括禁用、归档、备用/轮换项。归档和停用只改变可见性/启用状态，不删除凭据；清掉当前快速队列也不能代替清除所有目标端点。
- **客户端留空不代表上游已清**：官方接入说明允许本机代理客户端不填 Key。要检查网关里的上游凭据，而不是凭客户端的空值或占位符验收；停止代理和关闭开机启动也不等于移除存储。若本机版本有额外入站认证，另列其目标凭据。
- **保存的渠道与实际文件分别清理**：保存渠道只保存配置档案，应用才改工具文件。按实际版本核对 Claude Code、Claude Desktop、Codex、Pi/OMP 等已发现使用端；未应用/未启用的档案也可能有独立 API Key、OAuth 和请求头。`profiles/claude_code`、`profiles/codex/<id>/` 等本机快照独立于真实 CLI；Codex 快照可同时含 `auth` 与 `configToml`。只清任意一层都不能验收，不打印完整 Profile JSON。
- **原配置和操作新增备份**：应用渠道前会备份原客户端配置；提取还可生成 `claude.record.json`/`codex.record.json` 基线记录。沿当前版本设置和代码核实这些本机副本，不新建带密钥回滚包。若需要应用/恢复配置，先完成它们，再清理并复核最终 live 配置与动作新生成的备份，避免旧 Key 被写回；不以恢复默认/原配置作为清理捷径。
- **导入、导出与同步**：CC Switch 迁移会把可识别供应商导入为 CC Mesh 端点，导入项可能默认禁用。不能认定来源工具已清理，将本机已发现来源与导入后的独立副本分别关联到清单，按各自授权处理。同步页的本地备份、导出及已下载 WebDAV `.db` 文件可能含密钥；WebDAV 自身账号/密码也是独立凭据。只处理获准本机副本和同步凭据，保留云端文件，不点击远程删除、不上传清理后的数据库覆盖远端。

该提交的 WebDAV 数据库备份配置白名单仍包含 WebDAV 用户名/密码；JSON 导出虽排除 WebDAV 配置，仍可包含端点及多凭据 Key。不能因字段名叫“安全配置”或只排除了一类密码就把整个备份标为无秘密；本机副本按实际格式和获准范围分别处理。

JSON 导出的端点查询会排除归档项，因此空导出包不能证明原库没有 Key。仅依据已核实位置补查异常同步/恢复可能留下的 `ccmesh_backup.db`、`ccmesh_restore.db` 临时副本，不遍历整个临时目录，不为验证创建新导出或触发 WebDAV 同步/恢复。

按当前版本支持的方法选择性移除目标密钥/端点/渠道中的认证字段；混有非认证配置、对话或统计的数据不能整库删除。正常重开后分别核对端点多凭据、渠道、真实客户端和本机备份/迁移来源。目标服务需要重新提供上游凭据才算达标；不发送连通性测试、模型发现或对话请求来验证。当前任务依赖网关时最后处理并先交付接续步骤。

## 其他切换工具、网关与未知版本

发现名称不明确的 Switch、网关、中转客户端、便携版或分支版本时，先依据本机程序元数据、设置中的官方项目地址确定身份，再核对该版本支持的供应商/认证类型、存储位置和写入目标。无法确定就保留“产品/存储待核实”，不认定为 CC Switch 或 CC Mesh、不猜路径、不跳过。不能只发现客户端就结束；本地配置指向另一个本机代理时，将该已发现代理及其上游凭据存储关联到清单，不探测远程网关或局域网。

统一沿“管理器 → 实际使用端 → 环境/代理 → 备份/恢复”检查。没有单独登录按钮但保存 API Key 的工具仍属于凭据清理对象；真正无认证的本地模型可标为不适用并说明依据。

## 执行与验收

1. 按已授权清单准备精确目标和保留项。关闭自动同步/备份/恢复写入时区分本机与云端；正常停止相关程序，不强杀承载未保存工作或当前任务的进程。
2. 优先当前版本支持的密钥删除、认证移除和注销；需要离线编辑时，遵循[精确存储处理条件](local-reauth.md)，只改已验证 schema 的目标字段。无可信方法就标记待处理。
3. 重开管理器与相关客户端，检查目标全部密钥槽/认证字段已移除且不被恢复。保留供应商名称、端点或模型列表本身不代表凭据残留；星号遮挡、禁用开关或无效占位符也不能证明删除。
4. 只查看本机配置状态、认证提示及恢复来源，不重新输入旧 Key，不发送聊天、连通性测试、余额查询或拉取模型列表。正常网络下“要求重新配置凭据”与完整存储核对共同作为证据；单一网络错误不能验收。无法观察行为则记“已移除，使用端待验证”。
5. 对每个目标分别记录：管理器、使用端、环境/代理、已发现副本、恢复入口、本机验证、远端有效性。仍有任一获准副本或恢复入口未处理，标为部分完成，不能统称已清干净。

SQLite 记录移除、WAL/日志和 LevelDB 旧记录属于不同层面；普通设置删除不证明介质字节不可恢复。对已确认的日志/数据库残留仅采用该版本可靠且在授权内的方法，不在运行中删 WAL、不擦除混合数据整库、不做未经核实的压缩或覆盖。需要更强的不可恢复要求时单列设备擦除流程。

供应商云端 Key 若未撤销，记录“只移除本机，远端未撤销”；需要轮换时列为独立动作，尤其注意共享项目/其他设备依赖。官方依据见[来源](sources.md)中的 AI 工具部分。
