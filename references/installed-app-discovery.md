# 本机应用发现与覆盖清单

用于离职交接的第一轮只读盘点。目标是找出这台电脑上实际存在、供目标用户使用的应用，再逐个判断其本机认证状态；不根据一个预置软件名单声称已经覆盖整机。仅创建或修改 Skill 时不运行本流程。

发现阶段不退出账号、不启动未运行的应用、不卸载、不删文件，也不以“检查 Token”为名读取认证内容。应用安装位置、用户数据位置和凭据存储位置是三种不同证据，不能互相代替。

## Windows：按证据合并发现结果

确认实际目标用户。若终端属于管理员、服务账号或另一个用户，当前进程的 `HKCU`、Appx 和开始菜单不代表待交接用户，记录范围差异并在正确用户会话中继续；不要默默改扫全部用户。

### 1. 卸载注册表：只读四个值

检查当前用户和本机安装登记，兼顾 32 位与 64 位视图：

- `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall`
- `HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall`
- 64 位系统对应的 32 位卸载视图，通常显示为 `HKLM\Software\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall`；当前用户如有独立的 32 位卸载登记也纳入。

使用注册表只读 API/PowerShell 注册表提供程序，逐项按名称获取 `DisplayName`、`DisplayVersion`、`Publisher`、`InstallLocation`。可以在本机内部保留来源视图和子键标识以去重。不要先读取整条注册表记录再用输出过滤假装只读了四个字段。

不读取、不运行 `UninstallString`、`QuietUninstallString`、`ModifyPath` 或其他命令字段；不调用卸载器或安装修复程序。不得使用 `Win32_Product`、`wmic product` 或其 CIM 等价查询：这类枚举可能触发 MSI 一致性检查与修复，并不是无副作用的发现方法。

登记存在只证明有安装记录，可能是卸载残留。`InstallLocation` 为空也不能证明软件不存在。不要仅按 `DisplayName` 去重：同名软件可能有不同版本、发行渠道或独立配置。

### 2. 当前用户的 Appx/MSIX

使用当前用户范围的 `Get-AppxPackage`，输出限于名称、版本、发布者、包标识、安装位置和是否为框架等必要元数据。不加 `-AllUsers`，不指定其他用户，不访问远程主机，不读取包内用户数据。

应用包与运行库/资源包分开标注。运行库可以归为“无独立账号功能，不适用”，但保留其发现和分类依据；不要把它误列为有待注销的应用。命令不可用或权限不足时记录来源未覆盖，不以安装工具或提升权限作为默认补救。

### 3. 开始菜单与快捷方式

优先使用 `Get-StartApps` 取得当前用户应用的名称与 AppID。必要时补查当前用户和共享开始菜单中的快捷方式名称、扩展名，以及已确认本地快捷方式的目标程序路径；不枚举其他用户的开始菜单。

快捷方式只解析目标路径，不读取或输出 `Arguments`、URL 查询串、工作目录配置或完整 `.lnk` 内容，也不执行快捷方式。遇到 UNC、网络驱动器、远程 URL 或跨出获准范围的联接点，记录为外部目标，不跟随访问。共享开始菜单的入口不意味着当前用户拥有该应用的账号或有权清理其他用户数据。

### 4. 当前用户已运行进程的有限元数据

运行中应用可补足便携软件线索。只查询进程名称、PID、会话号及在当前权限下可取得的可执行文件位置；采用字段白名单，不请求 `CommandLine`，不读环境变量、进程内存、窗口标题或打开文档列表。

如使用 `Win32_Process`，查询必须显式列出所需字段，不能 `SELECT *`。可用 `GetOwner`/`GetOwnerSid` 核实进程是否属于目标用户，再保留目标用户的候选项。会话号只能缩小范围，不能替代所有者核验。无法确认所有者或读取路径时标记“未知/不可访问”，不提升权限、不结束进程。PID 可能消失或复用，后续操作前需重新核对程序身份。

### 5. 有界补查便携软件与自定义位置

只根据已发现的快捷方式、安装登记、目标用户进程或用户明确提供的目录，检查确切本地文件或有限目录层级。提前限定目录、深度、条目上限和时间；达到上限则报告未覆盖部分。

不递归扫描所有盘符、所有 `Users`、整个 AppData、远程磁盘或云盘，不跟随重解析点进入其他位置，不打开每个配置文件找账号。便携软件没有卸载登记是常见覆盖缺口；无默认目录命中、无进程或某一个发现源无结果，都不等于该软件未安装、未登录或已清干净。

已卸载应用若留下本机资料线索，应另列“疑似残留，待核实”，不能直接删除。WSL、虚拟机和容器中的应用可能不在宿主清单内；有明确证据或用户要求时再扩展这些隔离环境，否则在交付中列出边界。

### 6. 已发现浏览器/IDE 的本机应用与登录扩展

全机任务发现浏览器或 IDE 宿主后，应有界核对目标用户的配置文件、已安装 PWA、扩展/插件清单，不等待它们出现在卸载登记中。通过宿主支持的管理界面、只读清单命令或已核实的安装元数据，仅读取名称、ID、版本与宿主/配置文件关联；不打开扩展存储、会话、历史正文或插件密钥设置。

每个发现的 PWA 或可能持有独立登录的插件都关联到具体宿主实例，并检查是否有独立认证；未知插件的账号能力保留“待核对”。无法读取某个 Profile/插件清单时，给该宿主增加明确的覆盖待办，不把宿主已退出等同于插件已退出。浏览器内普通站点会话由该 Profile 的站点数据流程处理，不枚举用户在互联网注册的全部服务。

## 合并与逐应用状态

以实际发现证据建立总表，不把下面的品牌举例逐个当作本机已安装软件。合并同一应用的多个发现源，保留可区分的安装路径、版本、渠道或配置实例；同一品牌的个人版、企业版、商店版、便携版不能无依据合并。

**每个发现的应用或尚未排除的应用候选都必须有状态行。** 不认识的名称也要保留，不能只输出 QQ、微信、飞书而静默漏掉其他应用。纯系统组件/运行库可以标为不适用并说明原因；尚未核实是否有账号功能的应用不能提前标为不适用。

建议字段：

| 字段 | 记录要求 |
|---|---|
| 应用与实例 | 名称、版本/渠道、配置实例；本机内部保留稳定标识 |
| 存在证据 | 安装登记、包、菜单、已验证本地程序、当前用户进程或仅残留目录 |
| 归属和类别 | 当前用户/本机共享/未知；应用类别只用于路由 |
| 认证状态 | 已知有账号、未登录、需核对、无账号功能；发现阶段通常为需核对 |
| 范围与动作 | 本次是否获准；注销、移除此设备授权、清除精确本地认证存储，或仅盘点 |
| 状态与证据 | 待核对、待用户/管理员、已执行未验证、已验证需重新认证、用户反馈完成、不适用、失败/跳过及具体原因 |
| 复核与未覆盖项 | 实际验证方式、阻塞项、版本差异或未检查的配置实例 |

公开聊天和报告仅保留任务需要的信息，账户名、企业路径和本地用户名可使用代号。不要为了展示表格收集账号正文或认证内容。不能把软件数量当作已退出账号数量。

以下只用于识别已发现应用、联想到可能的登录入口；名称、版本和功能均须现场核对。未安装的软件不安装，不为凑齐类别而额外扫描。出现未列出的应用也走同一通用流程。

## 已知和未知应用共用的重新认证路线

发现清单完成后，按 [本机重新认证](local-reauth.md)、[应用退出流程](app-signout.md) 和已获准范围处理；浏览器转入 [浏览器流程](browsers.md)，开发/系统凭据转入 [凭据与资料流程](credentials-and-data.md)。

1. 核实当前版本、目标账号/实例以及标准注销、设备授权管理入口。没有专用说明时查该应用当前官方帮助或可用界面，不臆测 Token 文件名，也不把所有 Electron 应用视为同一存储布局。
2. 对每个已获准目标优先执行受支持的注销或移除此设备登录授权；继续检查是否还可用本地刷新凭据、免密授权、系统凭据库、插件、关联账号或 SSO 自动恢复。
3. 需要精确删除认证存储时，先证明其版本、账号归属和用途，并区分聊天、文档、存档、下载和配置。未知应用无法可靠区分认证与业务数据时，保留该状态行，给出官方注销/人工核验路径，不能靠删除整个目录声称成功。
4. 正常重开目标应用，验证目标账号必须重新扫码或完成新的交互认证；关闭程序、取消自动登录、清缓存、卸载或界面暂时变为登录页都不是充分证据。到新的认证挑战处即停止，不实际重新登录建立会话。
5. 仍能一键登录或经 SSO 恢复则尚未达到目标。若进一步处理会扩大到 Windows 系统账号、全设备下线、企业管理或他人账号，列明范围和待办，继续其他独立的已授权项。

本流程覆盖的是“实际发现并成功核验的应用”。没有通用目录删除方法能保证未知应用的所有会话或服务端权限 100% 失效；最终按 [验收](verification.md) 分别报告发现范围、已验证项、未知和未覆盖项。

## macOS / Linux 简短入口

- **macOS**：只读列出 `/Applications`、当前用户 `~/Applications` 的应用包名称与必要版本/包标识，结合当前用户的程序进程元数据补足便携/自定义位置。安装登记或工具清单只作交叉证据，不默认递归读取 `~/Library`、其他用户目录、网络卷或应用容器。Keychain、Apple 账号和应用会话在后续获准凭据流程处理。
- **Linux**：按当前发行版选择已有包管理器的本地已安装清单，区分系统包与用户应用；补查当前用户及系统共享的 desktop 入口，只读取名称/应用标识等必要字段，不运行也不输出可能含秘密的 `Exec` 参数。Flatpak 分别核对用户/系统安装的应用清单，Snap 仅用已有本地清单；AppImage、自解压或自定义安装依本地线索有界定位。不为了盘点更新仓库或安装扫描工具。
- 两个平台同样不读取进程命令行或环境值、不扫描其他用户；每个发现应用都进入同一状态表。路径不命中或工具不可用只代表覆盖不足。

## 依据与维护

本页是发现策略与覆盖约束，不是已执行的盘点报告。官方资料核对日期：2026-10-29。工具或系统版本变化时核对字段、作用域及是否会产生副作用。

- [Microsoft：Windows Installer 卸载登记字段](https://learn.microsoft.com/en-us/windows/win32/msi/uninstall-registry-key) — 核实四个安装元数据字段的意义。
- [Microsoft：查询已安装软件及 Win32_Product 的副作用](https://learn.microsoft.com/en-us/powershell/scripting/samples/working-with-software-installations) — 注册表是发现源之一，并不保证发现所有软件。
- [Microsoft：Get-AppxPackage](https://learn.microsoft.com/en-us/powershell/module/appx/get-appxpackage) — 用户范围、包清单与跨用户参数。
- [Microsoft：Get-StartApps](https://learn.microsoft.com/en-us/powershell/module/startlayout/get-startapps) — 当前用户应用名称与 AppID。
- [Microsoft：Win32_Process](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-process) 与 [GetOwner](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/getowner-method-in-class-win32-process) — 可选择的进程元数据、所有者和不可访问情况。
- [Flatpak 官方使用说明](https://docs.flatpak.org/en/latest/using-flatpak.html) — 已安装应用与用户/系统安装范围。
